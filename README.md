# 镜稿

在 Codex 中直接说“调用镜稿”即可启动，也支持“使用镜稿”“启动镜稿”。展示名称统一为“镜稿”；内部标识与安装目录保留 `ecommerce-video-script-shared` 以兼容现有成员更新。仅给启动口令时，先根据已有资料选路，缺少资料再提示选择功能与补充。

镜稿用于创作电商视频完整脚本，统一支持三种功能：

| 功能 | 创作依据 | 交付 |
| --- | --- | --- |
| 产品原创 | 商品图片与已确认资料 | 原创口播、分镜、完整视频提示词 |
| 参考迁移 | 参考视频的结构、节奏和镜头 | 适配当前商品的独立脚本 |
| 文案转分镜 | 启动指令＋完整旧文案，默认逐字锁定 | 全局设定、分镜、完整母版、必要分段、后期交接与负面提示词 |

每次创作先读取站点当前发布的规则，完成后保存完整 JSON 和 Markdown，并通过成员身份上传归档。摘要、商品和标签用于整理，不替代完整脚本。

## 三功能使用说明

[打开网页版说明并复制启动提示词](https://scripts.wenran007.com/guide.html)。无需登录即可查看每个功能需要上传的资料、完整启动提示词与交付内容。下方也保留完整文字版，便于随时查阅。

## 商品图加一段起始提示词

上传商品图后，可以直接发送：

```text
调用镜稿，启动功能一。根据商品图，围绕“出门前觉得穿搭少了点东西”这个起始想法，直接输出完整脚本，其他创作细节由你决定。
```

系统会选定创意，完成商品依据与受众分析、完整口播、详细分镜、视频提示词母版、必要分段和后期交接，再按已配置的归档流程保存。只锁定一句开场时原样保留该句、原创后文；完整旧文案配画面仍走功能三。缺少未使用的材质、价格或 SKU 不阻塞出稿，必要商品依据和硬性约束冲突会明确指出。脚本交付不代表视频已经生成。

功能三可直接这样启动：

```text
调用镜稿，启动第三功能，文案保持不动，输出完整脚本。
【完整旧文案开始】
在这里粘贴完整旧文案
【完整旧文案结束】
```

复用本次明确对应的商品资料；没有关键缺口时直接完成脚本与归档。默认保留原文的字词、标点、空格和换行，不增加钩子或结尾口播。目标时长或商品事实与原文冲突时保留原稿，交付标明问题的草稿和处理选项；只有用户明确允许时才改写。此入口生成脚本，不自动生成视频。


Codex 的安装器也支持以下命令。将 `<skill-installer目录>` 替换为当前环境中该系统技能的实际位置：

```text
python "<skill-installer目录>/scripts/install-skill-from-github.py" --url https://github.com/lekker1233/ecommerce-video-script-shared/tree/main/ecommerce-video-script-shared
```

默认安装到 `$CODEX_HOME/skills/ecommerce-video-script-shared`，未设置 `CODEX_HOME` 时为 `~/.codex/skills/ecommerce-video-script-shared`。安装完成后在下一轮对话中使用；已有同名 Skill 时，先核对安装来源，再使用下方更新入口，避免重复安装覆盖。

## 首次加入网站

**接入前请确认：完整脚本、商品信息和标签会上传到你选择的站点，该站点管理员可以查看和整理；成员只能读取自己的脚本。本地图片、视频等素材文件不会自动上传。**

在 Skill 安装目录之外运行下列命令，将 `<Skill安装目录>` 替换为实际绝对路径。Windows 上，终端留在安装目录内可能阻止更新器替换该目录：


命令会说明上传范围，要求输入 `YES`，再隐藏输入邀请码。不要把管理员密码或管理员 API 令牌填入这里；每位成员使用独立邀请兑换自己的凭据。

网络中断时用原邀请码重试，可恢复同一次兑换。邀请码输错、过期或撤销后，尚未接入的用户可以明确换用新邀请：

这个选项不会替换已经连接的成员身份。已连接成员需要更换站点或身份时，应先保留本地稿件并与管理员协调。

## 日常创作和更新

说“调用镜稿”后，Codex 按入口说明执行两类检查：

1. **每天首次使用时检查安装更新。** 从本仓库 `main/ecommerce-video-script-shared/distribution.json` 获取版本清单，再从清单指定的 `v<版本>` 标签下载文件，逐项验证 SHA-256 后更新。没有常驻进程，也不创建后台定时任务；当天不使用就不会自动检查。
2. **每份新稿开始前读取网站当前规则。** `refresh` 获取站点已发布的七份创作规则，记录版本和哈希。进行中的任务固定使用开始时的版本，发布新规则不会改写正在创作的稿件。

安装更新命令同样从 Skill 安装目录之外执行：

```text
python "<Skill安装目录>/scripts/update_skill.py"
python "<Skill安装目录>/scripts/update_skill.py" --force
```

`--force` 用于当日再次检查最新安装版本。更新只处理 `distribution.json` 白名单中的 Skill 文件，并校验固定仓库、版本标签和文件哈希；网站规则接口只发布 Markdown 内容。

此前下载的旧安装包若没有 `scripts/update_skill.py`，需要先安装一次带更新器的新版，之后才能使用每日检查。旧包不会凭空获得新增程序；迁移时保留安装目录之外的成员配置和本地作品库。

若安装的是 `2026.10.20.2`，并在 Windows 上遇到 `whoami` 编码报错，该旧更新器无法启动。请从 Skill 目录外把旧安装备份到 Skill 扫描目录外，再用安装器安装当前版；保留 `$CODEX_HOME/ecommerce-video-script-shared` 中的连接与稿件。`2026.10.20.3` 已修正 SID 的字节读取方式。

规则刷新及完整稿件保存：

```text
python "<Skill安装目录>/scripts/shared_client.py" refresh
python "<Skill安装目录>/scripts/shared_client.py" save --input <完整任务JSON路径> --release-file <refresh返回的manifest.json路径>
```

保存后保留返回的脚本编号。修订时使用同一编号并指定父版本：

```text
python "<Skill安装目录>/scripts/shared_client.py" save --input <修订JSON路径> --release-file <本次manifest.json路径> --script-id <UUID> --parent-version <当前版本>
python "<Skill安装目录>/scripts/shared_client.py" show --script-id <UUID>
python "<Skill安装目录>/scripts/shared_client.py" sync --script-id <UUID>
```

`local_saved=true` 表示本地已保存；只有 `remote_sync.status=synced` 才表示站点已接收并通过完整内容回读验证。上传失败保留本地稿件和待传状态，之后用 `sync` 补传。成员停用、认证失败或版本冲突时，应先联系管理员处理。

## 配置与稿件保护

成员配置、令牌、规则缓存和本地稿件独立保存在 `$CODEX_HOME/ecommerce-video-script-shared`，默认是 `~/.codex/ecommerce-video-script-shared`。它与 Skill 安装目录分开，安装更新不会删除或覆盖这些资料，也不会更换成员身份、上传站点或历史版本。

仓库内的 `release.json` 是发布时的七份规则快照，方便阅读三类创作流程和输出格式。实际新任务仍以网站 `refresh` 成功返回的版本为准；无法确认最新规则时，客户端会报告错误，不把旧快照冒充当前版本。运行时更新检查失败时也应说明实际状态，不宣称已经更新。

### 资料怎么准备

同一聊天里已经提供并确认的同一商品资料可以复用；新聊天或换商品时重新提供。上传多个商品、颜色或款式时，写清这次用哪一个；有多个参考视频时标明主要参考哪条、其他参考什么。

商品资料建议包括清晰整体图、与本次卖点有关的细节图，以及已有的商品名称、款式、参数或详情说明。图中可见外观与材质、尺寸、性能、价格等文字事实分开提供。未知内容留空即可；只有本次确实要讲某个卖点时，才需要提供其依据。无需为开始创作补齐所有参数或填写完整表格。

资料可以直接上传或粘贴，也可以给出当前任务实际可读取的文件位置。链接无法读取时，补文件或可读内容；文件名本身不能代替素材内容。

### 功能一｜商品图＋想法，原创完整脚本

#### 需要上传或填写什么

| 类型 | 内容 |
| --- | --- |
| 必需：商品依据 | 当前目标商品的清晰图片，或已经核实、足以识别商品的资料。已有同款资料可直接复用 |
| 必需：启动要求 | 复制下面的启动提示词；没有创意时可直接让 Skill 根据商品决定 |
| 选填：已确认卖点 | 本次要强调的材质、尺寸、功能、价格等；只提供确定内容 |
| 选填：创作要求 | 受众、使用场景、时长、风格、画幅、语言、指定开头、人物或字幕限制 |
| 选填：表现方式 | 自动选择、模特实景、产品纯细节，或明确要求两版 |

无需提供参考视频或旧文案。商品外观完全没有图片依据时，不会假装看过商品图；影响准确展示的部位可能需要补图。

#### 直接复制这段

```text
调用镜稿，启动功能一“产品原创”。以本次已上传、粘贴或在当前对话中明确确认的同一商品资料为依据，直接创作一套完整带货视频脚本。根据商品选择主要卖点、受众场景、开头和表现方式；我没有特别要求时自动选择一套主稿，不停在创意选项等待我确认。若我明确要求“两版”，分别完整交付模特实景版和产品纯细节版，并分别归档在同一项目。

先区分图片可见信息、资料确认的事实和未知项，不能猜测材质、性能、价格等商品事实。没有可读取的商品依据、商品身份或来源冲突、必要卖点缺少依据、锁定开头或硬性时长无法兼容时，集中提出必要问题；其余创作缺项按功能一规则补齐并说明。若我指定“开头原样保留”，只锁定该开头，后文继续原创，不静默改字。

资料充分时连续完成任务设定、商品依据与创意理由、完整口播、带时间和对应台词的详细分镜、可整体复制的完整视频提示词母版、必要分段及后期交接。声音默认后期旁白，画面生成提示词不生成人声；生成画面不叠加字幕，后期字幕单独说明。我明确要求无人手、无口播或无字幕等限制时，贯穿分镜、母版和每个片段执行。

检查商品、口播、动作、时间轴和提示词一致后，按已有配置归档完整稿，报告脚本编号、版本、完整稿位置以及实际本地保存和网站同步状态；同步失败保留本地稿并说明待补传。本次只完成脚本和提示词，不生成音视频或发布成片。
```

有想法时，在这段后面加一句即可，例如：

```text
本次想法：突出日常通勤使用；做15秒，产品纯细节，不出现人物和手部。其他创作细节由你决定。
```

**缺省设置：**一套主稿；从 15 秒短版试排，必要时可建议更长并解释；9:16、中文普通话、后期旁白。你明确指定的时长属于硬约束，不能被默认值覆盖。“产品纯细节”可以包含手部操作；完全不要人手时要明确写出。

**你会收到：**商品与创意依据、全局设定、完整口播、详细分镜、完整母版、必要分段、后期交接和归档结果。

### 功能二｜参考视频＋商品资料，拆解迁移到完整脚本

#### 需要上传或填写什么

| 类型 | 内容 |
| --- | --- |
| 必需：参考依据 | 优先上传可读取的视频文件；希望分析口播和声音时保留原音轨 |
| 必需：目标商品 | 自己商品的名称/款式、清晰图片及本次用得上的真实资料，不能只给竞品资料 |

| 选填：参考重点 | 希望借鉴整条结构，还是开头、展示顺序、节奏或某个片段 |
| 选填：创作要求 | 受众、使用场景、目标时长、画幅、语言、风格、指定开头及禁用项 |

视频暂时无法读取时，可以补关键帧、逐字稿或明确的文字描述，但拆解范围会相应缩小：静帧只能确认可见状态，逐字稿只能支持语言结构分析，用户描述会标明来源。完全没有可分析的参考依据时，需要先补充。

#### 直接复制这段

